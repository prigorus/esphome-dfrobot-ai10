# Experimental controls and recovery (develop)

Hardware log 2026-11-26, firmware v2.30-QRXF-PV: B0 read succeeded with A0 0C 4B 00 (USB 2.0 ISOC, 12 Mbps, JPEG 75, normal orientation). DB writes 00 and 01 returned rejected; F9 02/03 and F4 had no reply, F5 was not transmitted. No physical LED effect was reported. The LED test now sends F9 02 and F9 03 80 ms apart without requiring an acknowledgement. Completion is reported as unconfirmed (0xFF); no authorization event. Explicit stop during the pulse sends OFF. Recovery uses reset plus a successful idle status reply before starting fresh verification. DB write and IR test entities are disabled by default; previously enabled entities may remain enabled in HA. Do not use them in production without hardware confirmation.

The door package enables bounded recognition recovery (three attempts, 1.5 s between attempts), preserving the previous timeout/attempts. Recovery never retries enrollment, deletion, UVC writes or image transfers. A missing or rejected reset/status cannot authorize. Explicit stop/reset cancels scheduled recovery. A command echo cannot fully distinguish late replies of the same command: physical verification remains necessary.

Optional substitutions: ai10_repeat_delay_ms (100..5000, default 1000), ai10_fast_capture (false by default; reset-only pause and reuse a verified idle reset), ai10_incremental_directory (false by default; cache update after confirmed deletion or individual enrollment record). Keep conservative defaults until hardware tests; perform full refresh if database changed externally. Existing entity IDs and normal YAML stay unchanged. ai10_recognition_recovery defaults true in door package and false in standalone component.

B1 UVC write remains explicit API action; read original settings and change only quality to test UART JPEG size. Restore original quality 75 after testing. No threshold, duplicate-check, coordinate or firmware-update changes. No physical confirmation of palm-only or faster scan cycles yet.

The camera now backs off repeated failed archive attempts up to 15 minutes (or the configured interval if greater), while retaining the same protected JPEG. This is RAM-only; a restart loses unarchived images. Filenames retain the existing timestamp convention; uncertain acknowledgements can still produce duplicates. Failed or interrupted enrollment/deletion invalidates uncertain cached user data. A query-user request no longer overwrites an in-flight deletion UID.
